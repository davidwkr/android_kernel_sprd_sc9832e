# DW100U DTS for the 4.14 tree

Files in `arch/arm64/boot/dts/sprd/`: `sp9832e-1h10-dw100u.dtsi` (common), `sp9832e-1h10-dw100u-silver.dts`
(firmware V11H) and `sp9832e-1h10-dw100u-v13m.dts` (firmware V13M), panels in `lcd/lcd_co5300_oled178_mipi.dtsi`,
`lcd_co5300_oled204_mipi.dtsi`, `lcd_co5300_oled206_dw100u_mipi.dtsi`, `lcd_co5300_oled_213_mipi.dtsi` (new) and
`lcd_co5300_oled1952_mipi.dtsi` (the DM63 file, see below). Ground truth is the decompiled stock DT of each unit
(`devices/dw100u-silver/stock.dts`, `devices/dw100u-v13m/stock.dts`, 4.4 tree). The layout and every project decision
follow `devices/dm63/DTS_414.md` and `devices/dm63/PANEL_414.md`; read those first. Compile only
(`devices/merge_watch_414.sh $B`, `make O=$B ... dtbs`): both dtbs build, and decompiled with `dtc -I dtb -O dts`
they show the same warning kinds as `sp9832e-1h10-dm63.dtb` (one fewer, the DM63 rotary node). Nothing was run on a watch.

## Silver against V13M, and the structure chosen

`diff` of the two stock DTs (62 lines) gives one phandle label and the battery node plus the keys. Everything else
(memory, reserved-memory, regulators, buses, sensors, touch, 23 panel nodes, WCN, modem, ion, pinmux) is identical.

| | silver (V11H) | V13M |
|---|---|---|
| chg-end-vol / chg-end-vol-check / rechg-vol | 4395 / 4390 / 4320 mV | 4430 / 4420 / 4370 mV |
| cnom / rint | 940 mAh / 590 mOhm | 1079 mAh / 359 mOhm |
| adp-sdp/cdp/dcp/unknown-cur | 650 / 650 / 650 / 630 mA | 800 / 800 / 800 / 780 mA |
| temp-support | 0 (no battery NTC) | 1 (NTC, own temp-tab-val) |
| jeita-cur-tab (mA), zones 0..5 | 0 300 600 0x7fff 700 0 | 0 500 800 0x7fff 800 0 |
| jeita-cccv-tab | 4400 mV | 4450 mV |
| ocv-tab-vol | silver battery | own table |
| keys | Volume Down (ap_gpio 46, 150 ms), Power, Function (ap_gpio 44, 0x57) | Power, Function (code 0x43, ap-eic pin 12) |

Decision: one common dtsi plus two small dts. The dtsi holds everything shared and defines the labels `bat` (battery),
`cm` (charger-manager) and `keys` (gpio-keys) with the shared properties; each dts overrides per-unit properties
through those labels (battery profile, jeita table, full battery voltage, the unit's keys). Nothing is duplicated, the
two units cannot be mixed up by accident (each dts names the other as wrong). The SPEC.md rule "never use the other
unit's tree" holds for the dts files, the dtsi alone is not a board.

## Charging values

Sources: the stock `battery` node of each unit; conversion identical to `devices/dm63/DTS_414.md` ("Battery data",
"Stock JEITA table"). Common to both units: `chg-end-cur` 60 mA (`charge-term-current-microamp`, `cm-fullbatt-current`),
`alm-vol` 3450 mV (`voltage-min-design-microvolt`), `soft-vbat-uvlo` 3050 mV (`cm-shutdown-voltage`), `ovp-stop` 6500 /
`ovp-restart` 5800 mV (`sprd,ovp-microvolt`, `cm-charge-voltage-max`, `cm-charge-voltage-drop`), `chg-timeout` 21600 s
(`cm-charging-max`), adapter current limits 500 / 1500 / 3000 / 500 mA (second cell of `charge-sdp/cdp/dcp/unknown`),
jeita temperatures 900 1000 1100 1450 1500 with recovery 930 1030 1130 1420 1470 (offset 1000, -10..50 degC, 3 degC
hysteresis).

| | silver | V13M |
|---|---|---|
| CV (`constant_charge_voltage_max_microvolt`, stock `chg-end-vol`) | 4395000 | 4430000 |
| END_V / code the charger programs | END_V 1 (4300 mV) + 13 steps over the efuse calibration | END_V 1 + 17 steps |
| `cm-fullbatt-voltage` (stock `chg-end-vol-check`) | 4390000 | 4420000 |
| adapter current SDP/CDP/DCP, unknown | 650 mA, 630 mA | 800 mA, 780 mA |
| `cm-jeita-temp-table` (temp recovery uA uV) | `900 930 0 4400000`, `1000 1030 300000 4400000`, `1100 1130 600000 4400000`, `1450 1420 32767000 4400000`, `1500 1470 700000 4400000` | `900 930 0 4450000`, `1000 1030 500000 4450000`, `1100 1130 800000 4450000`, `1450 1420 32767000 4450000`, `1500 1470 800000 4450000` |
| `voltage-temp-table` | omitted (temp-support 0: the 4.14 gauge then reports a fixed 200 = 20 degC like the 4.4 driver) | stock 18 points (1052 mV at 75 degC .. 88 mV at 160 degC), identical to the DM63 table |
| OCV table, capacity, resistance | 21 points 4360 .. 3400 mV, 940 mAh, 590 mOhm | 21 points 4417 .. 3400 mV, 1079 mAh, 359 mOhm |

Representability: the SC2721 model (`sc2720_charger.c`, `SC2721_CHARGER_MAP.md`) takes END_V 4200 / 4300 / 4400 mV
plus `round(delta / 7.5)` code steps over the efuse calibration (default 0x20, 6 bit), bit 0 of the code cleared. All four
targets (4395 mV 13 steps, 4400 mV 13, 4430 mV 17, 4450 mV 20) use END_V 1 and stay within code 0x3f for a calibration
up to 0x32, 0x32, 0x2e and 0x2b. Above that, 4395 / 4400 mV fall back to END_V 2, but 4430 and 4450 mV are above the
4400 mV END_V ceiling and the 4.14 model refuses them (the charger returns an error). The efuse calibration of these
units was not read.

## Panels

Stock has 23 panel nodes in `lcds` (identical in both units). The five CO5300 nodes are converted with the DM63 method
(`PANEL_414.md`: `sprd,lcd-id` from the stock id, `sprd,refresh-rate` 60 from `fps`, `sprd,phy-bit-clock` from the stock
timing clock in kbps, vertical porches stock and horizontal 0 for the edpi selection, avdd / reset sequence from the
dsi child node properties, 128 MHz DPI clock assumption, ESD check off as stock, single command brightness form):

| Panel | lcd_id | size | init | note |
|---|---|---|---|---|
| lcd_co5300_oled204_mipi | ID5300204 | 368 x 448, 334000 kbps, default brightness 120 | 10 commands | the panel the silver unit reports (SPEC.md): `sprd,default-panel` of both dts; the V13M id was not read, same expectation |
| lcd_co5300_oled178_mipi | ID5300178 | 368 x 448, 334000 kbps | 15 commands | |
| lcd_co5300_oled1952_mipi | ID53001952 | 412 x 502, 409000 kbps | the DM63 file | stock node identical to the DM63 one except `aod-in` / `aod-out` (no 4.14 AOD port) |
| lcd_co5300_oled206_dw100u_mipi | ID5300206 | 412 x 502, 409000 kbps | 25 commands | differs from the DM63 206 init stream (vendor page writes `fe 40` ...), own file |
| lcd_co5300_oled_213_mipi | ID5300213 | 412 x 502, 460000 kbps, default brightness 25 | 8 commands | stock panel-name has the underscore; init stream differs from the DM63 213 (sleep out first, window 0..0x19b); brightness commands use data type 0x29 in stock |

Checks done by script on the stock bytes: init streams walk exactly (`type wait len-hi len-lo payload`), every stream's
`type` equals what the generic write path derives from the length (so `sprd,use-dcs-write` stays unset), the brightness
tables are the identity `51 00 .. 51 ff` (256 commands, replaced by the single command form), power sequences
`33 1 20, 50 1 20, 50 0 20, 50 1 50` / `50 0 20, 33 0 20` on all five. The 213 brightness command type 0x29 (2 byte
payload) goes out as 0x23 in 4.14 (the driver picks the type from the length). Not converted: the 18 other stock panels
(GC9B71, ST77916, ST7797, ST7801, CH13613, SH8601, 3311, dummy). The stock `sprd_backlight` (pwm, default 25) is not used
by the OLED panels, as on the DM63. AOD (`aod-in` / `aod-out`, DCS 0x39 / 0x38) has no 4.14 port.

## Risks for a first boot and a first charge

* Charge voltage: the stock jeita zone CV is above the stock `chg-end-vol` on both units (silver 4400 against 4395 mV,
  V13M 4450 against 4430 mV; the DM63 has it the other way round). The 4.4 `sprd_battery.c` caps the zone CV to
  `chg_end_vol_pure` (`sprdbat_current_adjust_by_status()`), and the 4.14 SC2721 charger now caps every CV request to
  the battery's `constant_charge_voltage_max` the same way, so the cell charges to 4395 / 4430 mV as in stock. Check
  CHGR_CTRL0 (0xec0) and the cell voltage on the first charges, with a current limited supply and attended. Check
  that the efuse calibration keeps 4430 mV (V13M) representable (calibration up to 0x2e).
* Adapter current: every request is capped to the adapter current (650 / 630 mA silver, 800 / 780 mA V13M, rounded down
  to the 50 mA step). The SDP charge current (650 / 800 mA) is above the 500 mA input limit in the second cell; stock has
  the same pair. Check the input current on a USB host port.
* No hardware charge timer, no ITERM / recharge programming, no OVP interrupt (see the DM63 note).
* Silver has no battery NTC: the gauge reports a fixed 20 degC, so jeita and the cold / hot limits never act there.
  The V13M NTC table was never checked on hardware (unit not connected).
* Touch on the V13M and the lcd_id of the V13M are unconfirmed; a wrong default panel gives a blank or shifted picture.
* The V13M Function key is taken as `eic_debounce` pin 12, same channel as stock ap-eic pin 12; not checked against
  the 4.4 eic driver. The silver Volume Down / Function keys sit on `ap_gpio` 46 / 44.
* i2c1 is 400 kHz as in stock; the qma6981 / och1970 / cst0xx probes fail without their chip (as stock).
* Reserved memory, regulators and the first boot console are as DM63: serial console `ttyS1` and USB only until the
  panel path is tested; the first DSI enable is skipped on purpose (see `PANEL_414.md`).
