# Android 14 GSI variant (stock 8.1 vendor)

A kernel and DT variant for booting an `ab` Android 14 GSI (TrebleDroid-based LineageOS 21, vndklite) on
top of the watches' **stock Android 8.1 vendor** (ADF hwcomposer, Mali r21p0 blob) on the DM63 and
DW100U silver. **Untested on hardware**: it only builds and its config and DTBs were checked offline.

System-as-root comes from a first-stage ramdisk built elsewhere, whose fstab mounts `/system` and
`/vendor`. See `A17_KERNEL.md` for the Android 14 kernel features and why 4.14 is the newest base.

## Build

    make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- O=$O sprd_sharkle_defconfig
    scripts/kconfig/merge_config.sh -m -O $O $O/.config \
        arch/arm64/configs/watch_414.fragment arch/arm64/configs/watch_414_adf.fragment \
        arch/arm64/configs/watch_414_a17.fragment arch/arm64/configs/watch_414_gsi.fragment
    make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- O=$O olddefconfig
    make ... O=$O Image modules dtbs

DTBs: `sp9832e-1h10-dm63-adf-gsi.dtb`, `sp9832e-1h10-dw100u-silver-adf-gsi.dtb`.

## Differences from the stock-8.1 build

`watch_414_gsi.fragment` replaces `watch_414_stock81.fragment`:

| | stock 8.1 | GSI |
|---|---|---|
| xt_qtaguid | on (takes the `owner` match name) | off, `xt_owner` on: Android 14 does accounting with eBPF |
| Low memory killer, OOM notifier | on, 8.1 lmkd tunes it | off: Android 14 lmkd uses PSI |
| PSI, memcg, cgroup pids/freezer | partly | pinned on |
| eBPF (`CGROUP_BPF`, `BPF_SYSCALL`, `BPF_JIT`, `XT_MATCH_BPF`, `NET_CLS_BPF`) | on in the defconfig | pinned, plus `NET_ACT_BPF` (was off) |
| timed_output + SPRD vibrator, SPRD_GSP, PID namespaces | on | kept: the 8.1 vendor HALs still use them |
| `PM_WAKELOCKS_LIMIT=0` | on | carried over: userspace wakelocks unlimited (not 100) |
| `PM_AUTOSLEEP` | on | not carried over (not a vendor requirement; does not set the wakelock limit) |
| DT `android,fstab` | present (8.1 init mounts from it) | removed |

Already on in the defconfig and pinned: `DM_VERITY`, `DEVTMPFS`, `BLK_DEV_LOOP`, `FS_ENCRYPTION`,
`INET_DIAG_DESTROY`, `COMPAT`. `CONFIG_COMPAT=y` is what the 32-bit ARM static first-stage init (and the
32-bit 8.1 vendor) needs; 4.14 has no `AARCH32_EL0` or `KUSER_HELPERS` symbol.

Not available in this tree: `CONFIG_UCLAMP_TASK` (5.3+) and the cgroup v2 freezer (`cgroup.freeze`, 5.2+).
`CONFIG_SCHED_TUNE` (the schedtune controller, `kernel/sched/tune.c`) exists but is off in the defconfig
and not pinned by the fragment; uclamp does not exist, so schedtune is the only candidate for
scheduling profiles.

Enabling the v1 freezer and pids does not make the Android 14 app freezer work. Per the review (the AOSP
android14 `task_profiles.json` was not reachable offline, so not checked here): LineageOS 21's default
Frozen/Unfrozen profiles write 1/0 to `cgroup.freeze` (cgroup v2), while this tree's v1 freezer exposes
`freezer.state` taking `FROZEN`/`THAWED`; and the compatibility scheduling profiles may select schedtune,
which is disabled. The GSI's `task_profiles.json` / `cgroups.json` need adapting (a vendor or `/system`
override), or the cached apps freezer has to be turned off (developer setting, or `device_config put
activity_manager_native_boot use_freezer false`). This is an open userspace integration item, not a boot
blocker (listed below). `MEMFD_CREATE`, `pidfd`, `userfaultfd` (a17), EROFS (a17) and binderfs (a17) need nothing more.

`# CONFIG_NETFILTER_XT_MATCH_QTAGUID is not set` does not show in the merged `.config`: the symbol
`depends on NETFILTER_XT_MATCH_OWNER=n`, so Kconfig hides it. It is off either way.

## Device tree

Android 10+ first-stage init reads `/firmware/android/fstab` from the DT before the ramdisk one. The
stock node (`sp9832e-watch-firmware.dtsi`) has `fsmgr_flags = "wait,avb"` on system and vendor and would
make it AVB-verify the GSI system. The `-gsi` boards include the `-adf` ones and
`/delete-node/ &{/firmware/android/fstab}`; the `vbmeta` node stays. The decompiled `-gsi` and `-adf`
DTBs differ only by that node.

## Not done / open

- Everything on hardware: boot, ramdisk fstab, lmkd on PSI, netbpfload on 4.14.
- The 8.1 vendor HALs (HIDL 1.0/2.0 era) against the Android 14 framework: vndklite and compatibility
  matrices are the ramdisk/GSI builder's side. 4.14 meets Android 14's minimum only; no later release.
- App freezer / scheduling profiles: `task_profiles.json` / `cgroups.json` adaptation or disabling the
  freezer (see above).
- Android 14's system suspend (`android.system.suspend`) uses `/sys/power/wakeup_count` and
  `/sys/power/state`; the kernel wakelock interface (`/sys/power/wake_lock`) remains, unlimited, for the
  stock 8.1 vendor HALs that use it.
