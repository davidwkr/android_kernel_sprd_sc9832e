# DM63 DTS for the 4.14 tree

File: `arch/arm64/boot/dts/sprd/sp9832e-1h10-dm63.dts` (included from `sc9832e.dtsi`, `sp9832e-mach.dtsi`,
`sc9832e-wcn.dtsi`, `sc2721.dtsi`). Ground truth for the hardware is the decompiled stock DT of the watch
(`devices/dm63/stock.dts` in the 4.4 tree). Compile only: `devices/merge_watch_414.sh $B` then
`make O=$B ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- dtbs` builds the whole tree, no dtc warning for this
file (the build dtc flags suppress the unit-address checks; decompiling the result with `dtc -I dtb -O dts`
shows only the same `reg_format` / `unit_address_vs_reg` warnings that the base files and `sl8541e-1h10.dtb`
already have, plus the placeholder panel node, which has the same shape as the one in `sl8541e-1h10.dts`).
Nothing was run on a watch.

Status column: mapped = value from stock in a 4.14 binding the driver reads; disabled-TODO = node left
disabled or property left out, stock values named; not needed = no 4.14 counterpart or no function on the
unit.

Notes:

1. reserved-memory. Stock regions (all copied): mpu0-dump@877ff000 0x1000, sipc-mem@87800000 0x3d0000,
   wcn-mem@88000000 0x300000, gnss-mem@88300000 0x15a800, pstore (ramoops) @8845a800 0x40000,
   cp-modem@89600000 0x4240000 (0x3fc0000 plus the 0x280000 debug region, `sprd,cpdbg-size`),
   audio_dma@8d840000 0x80000, sml-mem@94000000 0x20000, tos-mem@94020000 0x1fe0000,
   sh-mem@96000000 0x100000, iq-mem@98100000 0x4000000, camera@bdf64000 0x500000, fb@be464000 0xe10000,
   overlaybuffer@bf274000 0xa8c000. Differences to the sl8541e/mach.dtsi layout that were replaced: wcn and
   gnss at 0x84000000, cp-modem size 0x3fc0000, iq at 0x90000000, tos size 0x2e0000, ramoops at 0xbff80000.
   The `logobuffer@9e000000` of mach.dtsi is deleted together with the dpu `sprd,logo-memory` property that
   pointed at it (`sprd_dpu.c` treats it as optional), so the layout equals stock. Risk: U-Boot patches reserved-memory (cp debug region) and `memory` for the RAM size by node name; the
   node names are the stock ones, but this was not checked against the bootloader.
2. Regulators. 4.14 switches off an unused regulator in `regulator_late_cleanup()` unless it is always-on;
   stock `sprd,default-on` only switched them on at probe. Always-on in `sc2721.dtsi`: vddcpu, vddcore, vddmem,
   vddgen, vdd28, vdddcxo. Added here: vddemmccore (boot storage), vdd18, vddrf18, vddldomem, vddcamio (all on in
   stock, no consumer in this DT). Not forced (they have a consumer, which keeps them on): vddsdcore (sdio0,
   touch), vddsdio (sdio0), vddusb33 (hsphy). `sc2721.dtsi` has no counterparts of the stock `vddwpa`
   (dcdc@4), `vddsim0/1` (disabled in stock) and `vddrf15`.
3. Charger and battery CV. `constant_charge_voltage_max_microvolt` is the stock `chg-end-vol` 4480 mV, which the
   4.14 `sc2720_charger.c` programs as END_V 1 / code 56 with the default calibration (commit e2372d56f61f, as the
   4.4 `sprdchg_tune_endvol_cccv()` does), so the charger probes. The jeita zones then request the stock 4450 mV.
4. ADC channels. 4.4 `sprd_adc.c` numbers channels logically: even = big scale, odd = small scale, two logical
   per hardware channel (`SPRD_ADC_CHANNEL(logical, hw_id, ...)` in `sprd_sc2721_iio_channels`). The 4.14
   `sc27xx_adc` uses the hardware number. Stock `adc_temp` 1 -> hw 0 (base fgu `bat-temp` = 0), stock `adc_vchg`
   0x24 = 36 -> hw 14 (base `charge-vol` = 14), `bd-tsensor` 3 -> hw 1 (board NTC `pmic_adc 1`), `pa-tsensor` 5 -> hw 2,
   `chg-tsensor` 9 -> hw 4, `adc_vbat` 10 -> hw 5, `adc_isense` 0x10 = 16 -> hw 8 (THM). The board NTC table is the
   stock table: voltages 1131 .. 43 mV equal the sl8541e table, temperatures `(stock - 1000) * 100` mC.
5. Battery detect. Stock has no detect gpio and always treats the battery as present, so the inherited EIC 9
   reference is deleted and the gauge reports PRESENT = 1 without an interrupt. `cm-battery-stat = <2>` then
   always sees a battery.
6. USB. `dr-mode` is not read by the 4.14 musb glue (mode comes from Kconfig, `MUSB_DUAL_ROLE`). Stock typec
   `mode = 2`, `ext-ldo-sw = 0`, `tsleep = 0`: only `mode` has a 4.14 property.
7. gpio-keys. The stock code of the volume key is 0x43 (67), not `KEY_VOLUMEDOWN` (114); copied as is.
   `gpio-key,level-trigger` is not read by the 4.14 `gpio_keys`. The stock ap-eic bank 0 base is 0x40210000, the
   `sprd,sharkle-eic-debounce` bank 0, so pin 2 is the same hardware channel.
8. cst0xx. The driver calls `devm_regulator_get(dev, vdd_name)`, which resolves the DT property
   `<vdd_name>-supply`; stock did not need it (4.4 regulator lookup by name), so `vddsdcore-supply` is added.
   The `gpios` order is reset then irq, as the driver reads it. The pads of ap_gpio 144/145 are not muxed
   here: the stock DT has no pinctrl for them either (the sl8541e DTS sets them to GPIO function, but that DTS
   also turns SCL3/SDA3 into GPIOs, which cannot be copied since i2c3 is used). The 4.14 pinctrl default is untested.
9. SIPC and modem nodes. A property by property comparison of every node with a `sprd,name` (stock against the
   decompiled 4.14 DTB) found two differences in the base, both set to the stock value here: `spipe_wcn`
   `sprd,size-rxbuf` 0x2400 (base 0x1000) and `sdiag_lte` `sprd,size-rxbuf` 0x40000 (base 0x20000, whose comment
   says 256 KiB). The scproc `sprd,ctrl-reg/-mask/-type` triples are `syscons` in 4.14 with the same values
   (type 1 = pmu_apb, 0 = aon_apb). The syscon phandle values differ only because the labels differ. Stock has 8
   `seth_lte0..7` nodes with a `sprd,name`; the base has 14 `seth@N` without names (aliases seth0..13): not
   compared against the 4.14 `seth` driver, TODO if the cellular data path is ever used.

## efuse nvmem cell encoding (cccv_calib, cccv_calib_valid)

Sources: `drivers/nvmem/sc27xx-efuse.c`, `drivers/nvmem/core.c` (`of_nvmem_cell_get()` cell parsing),
`sc2721.dtsi` (`sprd,block-width` is not a property in 4.14), the 4.4 `sprd_2721_charge.c:57-72` and
`pmic_efuse.c`.

1. The efuse is a PMIC register block with 32 blocks (`SC27XX_EFUSE_BLOCK_MAX`) of 16 bits
   (`SC27XX_EFUSE_BLOCK_WIDTH` 2 bytes), same as stock (`sprd,block-num = 0x20`, `sprd,block-width = 0x10`).
2. The nvmem is byte addressed (`stride = 1`, `word_size = 1`, size 64). `sc27xx_efuse_read(offset, bytes)` reads
   block `offset / 2` and returns it shifted right by `8 * (offset % 2)`; `bytes` is limited to 2.
   A DT cell `reg = <offset size>` is therefore a byte offset and block N starts at byte `2 * N`.
3. `of_nvmem_cell_get()` also reads `bits = <bit_offset nbits>`. When `nbits` is non-zero the cell size becomes
   `DIV_ROUND_UP(bit_offset + nbits, 8)` bytes, and `nvmem_shift_read_buffer_in_place()` shifts by `bit_offset`
   and masks the top partial byte to `nbits`. The `reg` size given in the DT is overridden by that.
4. The 4.4 charger reads `blk0 = sprd_pmic_efuse_block_read(0)` and requires `blk0 & BIT(0)`, then
   `sprd_pmic_efuse_bits_read(BITSINDEX(13, 0), 6)` with `BITSINDEX(b, o) = b * 16 + o` (16 bit blocks), mask
   0x3f. Bit index 13 * 16 + 0 = 208: block 13, bit 0, 6 bits. The 4.4 SC2721 block read returns the raw
   `ANA_REG_EFUSE_DATA_RD` (the bit reversal is only for SC2723), the same value as the 4.14 driver.
5. Result: valid flag = block 0, byte offset `0 * 2 = 0x00`, `bits = <0 1>` (cell `cccv-valid@0`,
   `reg = <0x0 0x1>`); calibration = block 13, byte offset `13 * 2 = 0x1a`, `bits = <0 6>` (cell `cccv-calib@1a`,
   `reg = <0x1a 0x1>`). Both cells read one byte; bit 0..5 of block 13 sit in the low byte, so the high byte is not needed.
6. The cell offsets coincide with the existing base cells `efuse_blk0` (0x0, whole block 0) and `cc_cal` (0x1a, whole
   block 13, read by the typec node); the new nodes only add the bit selection and do not change those. The
   cells are named `cccv-valid` / `cccv-calib` because dtc would otherwise merge them with `calib@0` / `calib@1a`.
7. `sc2720_charger.c` `sc2721_read_calib()` reads `cccv_calib_valid` first (no BIT(0): default 0x20), then
   `cccv_calib` masked with 0x3f, and fails the probe if a cell is missing (no guessed default).
8. The efuse driver matches `sprd,sc2721-efuse` (second compatible of the base node), uses hwlock 12 and the
   `sc2731_edata` module-enable register 0xc08, which the FGU map shows is the same for the SC2721.

## Stock JEITA table to `cm-jeita-temp-table`

The 4.4 kernel of the watch applies this table: `sprd_battery.c` parses the `jeita-*` properties (line 2944),
selects and applies the zone at charge start (line 1325) and caps the zone current to the adapter current
(`chg_current_type`, line 222). The 4.14 port does the same: charger-manager applies the zone, and
`sc2720_charger_set_current()` caps every SC2721 request to the adapter current. The stock values:

| Stock property | Values |
|---|---|
| jeita-temp-tab | 900 1000 1100 1450 1500 (0.1 degC + 1000: -10, 0, 10, 45, 50 degC) |
| jeita-temp-recovery-tab | 930 1030 1130 1420 1470 |
| jeita-cur-tab (6 zones, mA) | 0, 100, 500, 0x7fff (no limit), 700, 0 |
| jeita-cccv-tab (6 zones, mV) | 4450 in every zone |

4.14 format: one entry `<temp recovery uA uV>` per temperature, temperatures keep the +1000 offset (the driver
subtracts 1000), zone z (between entry z - 1 and entry z) uses the current and voltage of entry z, zone 0 (below
entry 0) and zone N (above entry N - 1) stop charging. That maps stock zone z to entry z and drops stock
`cur-tab[0]` / `[5]` (both 0 = stop, same meaning):

| Entry | temp | recovery | uA | uV | From stock |
|---|---|---|---|---|---|
| 0 | 900 | 930 | 0 | 4450000 | temp-tab[0], recovery[0], cur[0] = 0, cccv[0] |
| 1 | 1000 | 1030 | 100000 | 4450000 | zone -10..0 degC: cur[1] = 100 mA |
| 2 | 1100 | 1130 | 500000 | 4450000 | zone 0..10 degC: cur[2] = 500 mA |
| 3 | 1450 | 1420 | 32767000 | 4450000 | zone 10..45 degC: cur[3] = 0x7fff, see below |
| 4 | 1500 | 1470 | 700000 | 4450000 | zone 45..50 degC: cur[4] = 700 mA |

Zone 5 (above 50 degC) and zone 0 stop charging. `0x7fff` means "no jeita limit", the adapter current of
`adp-*-cur` applies (450 mA, unknown adapter 430 mA); it is written as 32767 mA and the charger cap to the adapter
current brings it down, as in 4.4. The same cap limits the 0..10 degC (500 mA) and 45..50 degC (700 mA) zones to the
adapter current. Entries 0 to 2 have recovery above temp (lower boundaries,
a rising temperature enters the next zone once recovery is reached), entries 3 and 4 have recovery below temp (upper
boundaries). `charger-manager.c` takes that from the data for tables that do not have exactly four entries; the
four entry table keeps its original selection code.

## Charging state and unported protections

The charger probes and charges: the SC2721 charger driver programs CV (stock 4480 mV at probe, then 4450 mV by the
jeita zone), the charge current from the `charge-*-current-microamp` pairs and the jeita zone (capped to the adapter
current, then to the 1300 mA hardware maximum),
DPM 3, and the input OVP level (6500 mV) from `sprd,ovp-microvolt`. Charge stop at the temperature limits comes from
the jeita table and `cm-battery-cold/hot`; full-battery detection from `cm-fullbatt-*`.

Not ported, so not protecting a charge on this kernel (stock values in the DTS comments):
* chg-timer (SC2721 charge timer block, irq 7) and the stock `chg-timeout` is only covered by `cm-charging-max`
  in charger-manager (software timer, needs the kernel to run).
* fast charge (not relevant for 5 V input) and the charge watchdog (stock chg-wdt disabled).
* termination current (ITERM) and the recharge bit are not written; termination is only the software
  `cm-fullbatt-current` / voltage check, hardware termination stays at the chip default.
* the VCHG over-voltage and CV state interrupts (`chg-ovi-gpios`, `chg-cv-gpios`) and `ovp-restart`.

## Risks for a first boot

* First charge: no hardware charge timer, no hardware ITERM/recharge programming, no OVP interrupt. Charging
  limits depend on charger-manager running; do the first charges attended, with a current limited supply, and
  check the CV and the OVP register (CHGR_CTRL0/1 at 0xec0) against the values above.
* Every charge current is capped to the adapter current (450 mA, unknown adapter 430 mA, rounded down to the
  50 mA step) in the SC2721 charger; this cap is the only thing between a jeita or thermal request and the 1300 mA
  hardware maximum, so check it on the first charge.
* `regulator_late_cleanup()` can switch off rails stock keeps on (note 2); the ones without a consumer are
  forced always-on, a rail missing from that list that stock keeps on would be lost.
* Reserved memory differs from the reference board in six regions; a mismatch with what U-Boot or the modem
  firmware expects (cp debug region, WCN at 0x88000000) shows as a hang before the console.
* Display is off: first boot is serial console (`ttyS1`) and USB only. loglevel is 1 as in stock; raise it
  via the boot image command line for bring-up if the bootloader allows it.
* `INPUT_GPIO_ROTARY_ENCODER` is off in `sprd_sharkle_defconfig`; the crown does nothing without it.
