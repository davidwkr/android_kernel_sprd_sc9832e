# Android 10 VNDK 29 vendor (SL8541E_VNDK29 package) on the 4.4.302 kernel

Opt-in kernel config and DT variants for running the third-party Android 10 (VNDK 29) vendor image
of the `SL8541E_VNDK29` package on the DM63 and the DW100U silver with **this** kernel, instead of
the package's own closed 4.4.147 kernel (pre-rooted with KernelSU, `userdebug`, SELinux permissive in
the bootargs; never used here). Only the vendor image's userspace is wanted. **Untested on hardware**:
nothing here was booted; the configs were checked with `watch_verify` and the kernels, modules and
DTBs build. The package is third-party data of unknown origin; this work only read its boot image
(config, DTB) and the module files of its vendor image, nothing from it was executed.

## Use

```
scripts/watch_build.sh --newandroid --vndk29 DEVICE [OUTDIR]
# or WATCH_EXTRA_FRAGS="watch_newandroid watch_vndk29" scripts/watch_build.sh DEVICE
make ARCH=arm64 O=... sprd/sp9832e-1h10-dm63-vndk29.dtb sprd/sp9832e-1h10-dw100u-silver-vndk29.dtb
```

`watch_vndk29` goes after `watch_newandroid` (Android 10+ cgroups: `CGROUP_BPF`, `CGROUP_SCHEDTUNE`,
see `devices/NEWANDROID_44.md`; the package kernel has both too). The build goes to
`OUTDIR/DEVICE+watch_newandroid+watch_vndk29/`; stock builds and the committed `*_defconfig` files do
not change (`scripts/watch_defconfig.sh --check all` is clean).

## Kernel config (`arch/arm64/configs/watch_vndk29.fragment`)

Compared the package kernel's embedded config (3358 symbols) with the merged DM63 and DW100U configs.
Same differences on both devices:

| Option | Why |
|---|---|
| `SPRD_SIPC_STTY=y` | In the package kernel for its vendor. This tree's `stty.c` only binds `sprd,stty4bt`, which no DT (stock or package) has: inert until a node asks for it. |
| `SPRD_SIPC_GNSS_STTY=y` | In the package kernel (gnss HAL via `/dev/sttygnss0`, which the `spipe_gnss` DT node already gives through `SPRD_SIPC_SPIPE`). The symbol has no code in this tree; it only keeps the configs equal. |
| `SPRD_AUDIO_SIPC=y` | In the package kernel (AP to AGDSP channel under the vendor audio HAL). Binds `sprd,audio_sipc`, absent on this board's DTs, so it only adds the driver. Dependencies (`SPRD_MAILBOX`, `SPRD_AUDIO_MEMORY_MANAGER`) were already `y`. |
| `SPRD_VIBRATOR=m` | The vendor ships `sprd_vibrator.ko`; the stock configs build the driver in (the vendor's insmod would fail). Same driver and DT node. |

Left out on purpose:

| Option | Why not |
|---|---|
| `KSU`, `KSU_LSM_SECURITY_HOOKS` | KernelSU, a root backdoor. Never. |
| `IODEBUG`, `IODEBUG_BDI`, `IODEBUG_VFS`, `WCN_UTILS` | Debug (I/O debugging, WCN register read/write). No `SECURITY_SELINUX_DEVELOP` or bootarg change either: the DT bootargs of our boards stay as they are (no `androidboot.selinux=permissive`, no `loglevel=7`). |
| `WCN_BOOT` | The SDIO Marlin boot path of `sc23xx`; the watches use `WCN_PLATFORM`/SIPC (already `y`). Not needed for the SIPC `sprdwl_ng`/`sprdbt_tty`/`sprd_fm` modules. |
| `BACKLIGHT_PWM`, `TOUCHSCREEN_TLSC6X`, `INPUT_QMA6981_I2C` | Drivers of the DW99 board it was built for (`pwm-backlight`, TLSC6x touch, QMA6981 accelerometer); neither of our DTs has those nodes (we use `sprd_backlight`, hynitron/cst0xx touch, sc7a22). |

## Device tree (`sp9832e-1h10-dm63-vndk29.dts`, `sp9832e-1h10-dw100u-silver-vndk29.dts`)

Each includes the stock board DTS and only deletes `/firmware/android/fstab`: Android 10 first-stage
init reads the DT fstab before the ramdisk one, and the stock one has `wait,avb` on `/system` and
`/vendor`. The package DTB has only the `vbmeta` node there too; the vendor's own
`fstab.sl8541e_1h10` in the first-stage ramdisk (to be rebuilt from a trusted `init`) mounts them
(same approach as the 4.14 `-adf-gsi` variants).

Compared by node path and `compatible` (package DTB decompiled with `dtc`, ours from this tree):

- The package DTB's SIPC (`sipc-lte`, `sipc-wcn`, `sipc-gnss`, `spipe_*`, `stty_lte`, `sttygnss0`,
  `seth_lte*`, `ttyBT`, `fm`, `gnss_common_ctl`), `cpwcn_gnss`/`cpwcn_btwf`, audio codec/VBC/I2S and
  reserved-memory nodes are the same as ours. There is no SIPC tty, GNSS or audio channel to add.
- Package only: `heartrate,bd1xxx` (its heart-rate chip; ours has the `hrs3xxx` driver, plus
  `bd1xxx` in its own branch), `magnetic,och1970` (DM63 comparison), `rotary-encoder` and
  `sprd,sensor-sub` (DW99 board hardware). Not added: hardware our watches do not have.
- Ours only, which the package lacks: `tyhx,hrs3xxx` heart rate (both), `goodix,fingerprintree`
  (DW100U), `compass,af6837` (DM63), the DT fstab, and the panel set of our board (the package DTB
  has CO5300 1.78/1.95/2.04 and CH13613 2.04/2.13 panels only). All kept.
- Board data that differs and is kept ours: battery/FGU tables, CPU OPPs, touch size, sc7a22
  layout/IRQ GPIO, `i2c@70600000` enabled (HRS), GPU `syscons`/`syscon-names = "top_force_shutdown"`
  (only needed by the Mali r28p0 platform file once it is ported: add it with that port).
- Bootargs: identical to ours except the package's `loglevel=7` and `androidboot.selinux=permissive`,
  both not taken. `androidboot.hardware=sl8541e_1h10` matches the vendor's `fstab`/rc names.

## Vendor modules (`/vendor/lib/modules`, vermagic `4.4.147 SMP preempt mod_unload modversions aarch64`)

None of them loads on this kernel (vermagic `4.4.302+` here): all have to come from our build.

| Package module | Our build (`scripts/watch_build.sh`, `OUTDIR/DEVICE+.../`) |
|---|---|
| `sprdwl_ng.ko` | built (in-tree) |
| `sprdbt_tty.ko` | built (`sprdwcn_bsp/.../bluetooth/driver`) |
| `sprd_fm.ko` | built (`sprdwcn_bsp/.../fm/driver`) |
| `sprd_vibrator.ko` | built with this fragment (`SPRD_VIBRATOR=m`, collected by the script) |
| `mali.ko` (Midgard r28p0-01rel0) | **not replaceable yet.** `mali.ko` from this tree is r21p0 for the stock 8.1 blob; the vendor userspace is r28p0, a separate kbase port, pending its source. |

Use the modules of the same build as the `Image` (vermagic). The vendor's `modules.dep` lists them
without dependencies.

## What remains

- Mali r28p0 kbase port (and the `top_force_shutdown` syscon above); until then no GPU with this vendor.
- Vendor-side HAL transplants, none of which the package vendor has: Goodix fingerprint (DW100U),
  sensors HAL with HRS3xxx (both) and AF6837 (DM63), GNSS with our A-GPS patches (its 32-bit
  `gps.default.so` differs from the stock one), plus the stock services it lacks (see
  `devices/SL8541E_VNDK29_PACKAGE.md` in the 4.14 repo notes).
- The first-stage ramdisk from a trusted `init`, and panels of other hardware revisions.
- The package's provenance (messenger, no source, rooted kernel) needs the security team's review
  before any use on managed watches.
