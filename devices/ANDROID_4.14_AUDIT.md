# Android common kernel 4.14 audit

Input for the next step (backporting `aosp/android-4.14-stable` fixes in small reviewed batches). Analysis only: nothing was picked. Generated by `tools/ack_audit_414.py` (run `python3 -I tools/ack_audit_414.py OUT.tsv --config <watch .config>`), then curated by hand. The full per-commit table is the TSV the tool writes (`~/.cache/ack414.tsv` for this run).

## Method

1. Candidates: the 2016 non-merge commits of `aosp/android-4.14-stable` (014241ad77dd) that are not reachable from `v4.14.336` and whose subject starts with `ANDROID:`, `UPSTREAM:`, `BACKPORT:`, `FROMLIST:`, `FROMGIT:`, `CHROMIUM:` or `FROMDT:` (also inside `Revert "..."`).
2. Presence in this tree. There is no shared history, so everything is content based, first match wins:
   - cherry-pick sha or normalized subject found in the last 4000 commit messages: PRESENT (matched zero times in this run, the stable updates are one commit per release)
   - none of the touched files exist here: NOT-APPLICABLE
   - only docs, defconfigs, build config, other-arch files: NOT-APPLICABLE
   - otherwise per hunk: the whitespace-stripped post-image (context plus added lines) occurs contiguously in the HEAD file = applied; else the pre-image occurs = not applied; else unknown, decided by whether 80% of the added lines (len 12 or more) exist in the file. All hunks applied = PRESENT, none = MISSING, mixed = PARTIAL. A revert whose target is absent is NOT-APPLICABLE.
3. Build gate: `devices/merge_watch_414.sh` (sprd_sharkle_defconfig plus watch_414.fragment, no build). Each `.c`/`.S` file is resolved through the `obj-$(CONFIG_*)` chains and simple `ifeq/ifdef` blocks of the Makefiles: `y` built, `n` not built, `?` unresolved (headers, composite objects, conditional objects).
4. Class of MISSING/PARTIAL: (a) CVE or security wording in a fix or sensitive subsystem, (b) feature/infra or code not built, (c) other bugfix in built code. Keyword based; the table below was checked by hand against the tree.

Caveats:
- MISSING is an upper bound. 73 of the 716 have only unknown hunks (the vendor code diverged from the ACK context, so neither image matches). Spot checks found false MISSING where the vendor wrote the same fix differently (`binder: fix handling of misaligned binder object` is present at `drivers/android/binder.c:2248`). Check with a grep before picking.
- Many MISSING commits are features or series that need a base this tree lacks (inline encryption, f2fs compression and casefolding, dma-buf dentry_ops rework, SELinux sidtab overhaul, pidfd, tagged-address ABI, binderfs, Shadow Call Stack, CFI, init_on_alloc). Fixes on top of those are not applicable until the base lands.
- Config gate facts for this config: `DM_ANDROID_VERITY`, `ANDROID_BINDERFS`, `NETFILTER_XT_MATCH_QTAGUID` are not set (so the xt_qtaguid, binderfs and android-verity commits do not matter); `PSI`, `BPF_SYSCALL`, `XFRM_INTERFACE`, `USB_CONFIGFS_F_ACC`, `ION`, `F2FS_FS_ENCRYPTION`, `SDCARD_FS`, `UID_SYS_STATS`, `NETFILTER_XT_MATCH_QUOTA2` and `NETFILTER_XT_TARGET_IDLETIMER` are set.
- The 4.14.y stable diffs the vendor already took carry many ACK `UPSTREAM:` commits, which is why presence is high.

## Top 15 to backport first

Order is risk to a shipped watch first, then small and independent first. Take only the final upstream form of a series.

1. `ec932f3932e5` psi OOB write: local stack write by any process that can open /proc/pressure/*, three lines, no conflicts expected.
2. `21e1e64073ff` psi trigger UAF: local UAF in poll(), same file as 1; backport touches cgroup.c and psi.h, pick right after 1.
3. `921be923551b` bpf gso_size: crash path on IPv6-only or tethering setups using clat, small diff in one file.
4. `fe7096ab25ac` binder num_valid: restores the OOB range check in binder transaction parsing, one `*` to `/`.
5. `ae4a7b9165c7` binder cred euid: correct identity for sender_euid, `proc->cred` already exists so only the sender_euid line, the field and the open path change.
6. `bb80e7ded12e` xt_quota2 memset: kernel memory disclosure over netlink, trivial.
7. `a4873af07a5a` xfrm gro_cells leak: leak on every VPN interface teardown, two lines.
8. `33f17703cceb` xfrm dir check: closes the remaining unchecked sites with the existing `verify_policy_dir`.
9. `3af44e7d523f` f_accessory cancel work: UAF at gadget teardown, two lines.
10. `88409856fb88` f_accessory acc_release ordering: pair with 9 and 11; `6dff19ec15ca` and `ff547623ce6c` complete the `_acc_dev` lifetime fix.
11. `d5e62e55287d` f_accessory NULL dev check: host-driven NULL deref in acc_ctrlrequest, three lines.
12. `0ac69147fd8c` IDLETIMER resume: uninitialised use on every resume, small.
13. `2581e5be6555` + `6e6c15288df8` dma-buf release/f_inode UAF: needs the dentry_ops rework first, so a two-commit series and more testing; fixes a real UAF in ION/dma-buf lifetime.
14. `460dc7c31cef` uid_sys_stats double accounting: correctness of battery/uid stats the framework reads (add `24ae15a0f6da`).
15. `7b860d58c10c` idle tick retention: power saving on an idle watch, upstream scheduler fix with low risk.

Not picked on purpose: the 45 class (a) items beyond the above are SELinux/BPF policy features that need userspace and sepolicy changes, fscrypt inline-encryption fixes (no blk-crypto here), and CFI/SCS/KASAN build items.
