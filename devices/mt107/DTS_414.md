# MT107 DTS for the 4.14 tree

Files in `arch/arm64/boot/dts/sprd/`: `sp9832e-1h10-mt107.dts` and the new panel file
`lcd/lcd_co5300_oled213_mt107_mipi.dtsi`. Ground truth is the decompiled stock DT of the unit
(`devices/mt107/stock.dts` and `devices/mt107/SPEC.md` of the 4.4 tree, read only). The layout and every project
decision follow `devices/dm63/DTS_414.md`, `devices/dm63/PANEL_414.md` and `devices/dw100u/DTS_414.md`; read those
first. Charger and gauge references: `devices/SC2721_CHARGER_MAP.md`, `devices/SC2721_FGU_MAP.md`.
Compile only (`devices/merge_watch_414.sh $B`, `make O=$B ... dtbs`): the dtb builds with no dtc warning, and
decompiled with `dtc -I dtb -O dts` it shows the same 81 warnings, of the same kinds, as `sp9832e-1h10-dm63.dtb`.
Nothing was run on a watch.

Status: mapped = value from stock in a 4.14 binding the driver reads; disabled-TODO = left out or disabled, stock
values named; not needed = no 4.14 counterpart or no function.

## What is the same as the DM63

Diffed against the stock DM63 DT: root, memory, bootargs, the 14 reserved-memory regions (the decompiled
reserved-memory node of the dtb is identical to the DM63 one, no logo buffer), eMMC / SD delays and supplies, the 14
`sprd,default-on` regulators (same always-on additions as the DM63), USB, CPU supplies, board NTC table, SIPC / WCN /
modem / ion (base nodes plus the two stock rx buffer sizes), charger / FGU nodes, keys (Volume Down ap-eic pin 2, code
0x43, 50 ms; Power PMIC EIC 1, 0x74) and the rotary crown (ap_gpio 78 / 92). Vibrator, typec, poweroff, 7sreset come
from `sc2721.dtsi`.

Note 1. Which touch chip is fitted is not known. Stock enables all three. Both 4.14 drivers claim reset and irq in their
DT parse (`devm_gpiod_get_index` / `devm_gpio_request_one`), so when one has bound the other fails with -EBUSY before
it resets anything, and the one without a chip fails on the missing ACK and releases the gpios. Enabling both is
therefore the stock behaviour and safe. The DM63 and DW100U DTS disable the second one because their unit is known.

## Display

Stock `lcds` has 20 nodes; the U-Boot log of the unit shows `co5300_readid` returning `0x33 0x11`, so the panel is a
CO5300. The five CO5300 nodes are converted:

| Stock node | Compared with | 4.14 file |
|---|---|---|
| lcd5300178 (368x448), lcd53001952, lcd5300204 (368x448), lcd5300206 | byte-identical to the DW100U silver nodes (phandle lines ignored) | the DW100U dtsi (`lcd_co5300_oled178_mipi`, `..._oled1952_mipi`, `..._oled204_mipi`, `..._oled206_dw100u_mipi`) |
| lcd5300213 (412x502, 460000 kbps) | differs from the DM63 node (init stream has the vendor writes `fe 20`, `f4 5a`, `f5 59`, `fe e0`, `04 20` first; stock has aod-in / aod-out) and from the DW100U node (init stream, panel-name, brightness command type 0x23 here, 0x29 there) | new `lcd_co5300_oled213_mt107_mipi.dtsi`: 15 commands from the stock bytes (script checked: the stream walks exactly), `sprd,lcd-id` 0x5300213, `sprd,refresh-rate` 60 (stock fps), DSI 460000 kbps, single brightness command `23 0a 00 02 51 00` (stock table is `51 NN` with NN = 0..255), reset-on `<1 20>, <0 20>, <1 50>`, off `<0 20>` |

Panel node: avdd gpio 33, reset gpio 50, `sprd,avdd-on-delay-ms` 20, `sprd,avdd-off-delay-ms` 20,
`sprd,avdd-off-after-reset` (stock power-on 33 1 20, 50 1 20, 50 0 20, 50 1 50; off 50 0 20, 33 0 20, same on all five
nodes), fixed `power` regulator as on the DM63. Nothing in the five nodes needs the generic panel driver to do more than
the DM63 CO5300 does.

`sprd,default-panel` is NOT set. SPEC.md gives only the candidates (5300213 or 5300206 from the 412x502 touch size) and
states the unit's `lcd_id` is unknown; picking one would be an invention. Selection is by the `lcd_id=ID<hex>` that U-Boot
puts on the command line, as stock; without it the panel probe returns -ENODEV and the screen stays blank. TODO: read
`/proc/cmdline` on the unit and set `sprd,default-panel`.

Not converted (the unit has a CO5300): SH8601 x2, CH13613 x2, ST7801, ICNA3311, ST7797, GC9B71 x2, ST77916 x4, JD9855,
dummy HD. AOD (stock `aod-in` / `aod-out`) has no 4.14 port. Backlight: stock `pwm-backlight` is unused by the OLED.

The charger caps every zone current to the adapter current (420 mA, unknown adapter 400 mA, rounded down to the 50 mA
step as in the DM63 note) and every CV request to the battery maximum, so the 4400 mV zone CV becomes 4395 mV, as the 4.4
`sprd_battery.c` does.

Representability of 4395 mV in `sc2720_charger.c` (`sc2721_cv_model()`: programmed CV = 4200 + 100 * END_V mV +
(code - calibration) * 7.5 mV, code 6 bits with bit 0 cleared, END_V 0..2): it is representable for every efuse
calibration 0..0x3f, so the probe cannot fail on it.
* Default calibration 0x20 (efuse valid flag clear): END_V 1, code 0x2c, programmed 4390 mV.
* Calibration 0..50: END_V 1, code (cal + 13) with bit 0 cleared: even calibration gives 4390 mV (13 steps rounded
  down to 12), odd calibration 4397.5 mV (2.5 mV above the stock 4395 mV, the same rounding as 4.4).
* Calibration 51..63: the code would pass 0x3f, END_V 2 (4400 mV) with code (cal - 1) cleared of bit 0: 4392.5 mV for
  odd, 4385 mV for even calibration.
The efuse value of the unit is not known.

Not ported, so not protecting a charge on this kernel (as DM63): hardware charge timer, fast charge and charge
watchdog, ITERM and recharge bits, the VCHG over-voltage / CV state interrupts (stock `chg-cv-gpios` PMIC EIC 4,
`chg-ovi-gpios` EIC 6), `ovp-restart`. `cnom-temp-tab` / `rint-temp-tab` not mapped (units).

None for this DTS to build or probe. Optional: drivers for `btl,btl_ts`, `heartrate,bd1xxx`, `pressure,msp891`,
`compass,af6837` (all fitted in stock, none has a 4.14 driver), the camera sensors, AOD.

## Risks for a first boot and a first charge

* Display: no default panel; blank unless U-Boot passes `lcd_id`. Same first-enable-skipped and TE-pad risks as
  `devices/dm63/PANEL_414.md`. A wrong variant gives a shifted picture.
* Touch: three stock candidates, two mapped; if the unit has the BetterLife chip there is no touch.
* First charge: attended, current limited supply. Charge limits depend on charger-manager running; check CV (4390 mV
  expected with calibration 0x20) and the OVP field. Every charge current is capped to 420 mA by the adapter cap, the only
  thing between a zone request and the 1300 mA hardware maximum. Zone CV 4400 mV is above the battery maximum by design
  and is capped to 4395 mV.
* No battery NTC: temperature is fixed at 20 degC, the jeita temperature stops never trigger.
* `regulator_late_cleanup()` can switch off rails stock keeps on; the same five are forced always-on as on the DM63.
* Reserved memory equals the DM63 layout; a mismatch with U-Boot or the modem shows as a hang before the console.
* `INPUT_GPIO_ROTARY_ENCODER` is off in `sprd_sharkle_defconfig`; the crown does nothing without it.
